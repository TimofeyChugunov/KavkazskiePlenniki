# ADR-001: Идентификация гостевой корзины

## Статус
Принято

## Контекст
Покупатель может добавлять товары в корзину до авторизации (как гость). Необходимо надёжно идентифицировать владельца гостевой корзины и обеспечить слияние (merge) с авторизованной корзиной при логине.

## Рассмотренные варианты

**1. X-Session-Id заголовок (opaque UUID)**
Фронт генерирует UUID при первом обращении и передаёт в каждом запросе. Сервер использует как ключ корзины.

**2. Cookie (HttpOnly, server-set)**
Сервер устанавливает cookie при первом запросе. Браузер автоматически отправляет его. Требует серверной логики для установки/чтения.

**3. Временный JWT (без подписи или с коротким TTL)**
Гость получает JWT при первом обращении. Подпись не требуется — токен используется только для идентификации, не для авторизации.

## Решение
Выбран вариант 1 — **X-Session-Id заголовок**.

## Обоснование

**Совместимость с мобильными клиентами**: Заголовок работает одинаково на web, iOS, Android. Cookie требуют специальной работы с WebView/NSURLSession. JWT добавляет лишний payload (~200 байт на каждый запрос) без необходимости.

**Риск подделки идентификатора**: UUID — это не секрет, но подделка безопасна: злоумышленник может добавить товары в «чужую» гостевую корзину, но при логине владельца произойдёт merge с MAX(guest, auth), и реальный владелец получит максимум товаров. Нет риска перехвата сессии или компрометации данных. Строки сравнения нет — UUID не является токеном авторизации.

**Простота реализации**: Фронт генерирует `crypto.randomUUID()` при загрузке. Сервер просто читает заголовок. Не требует серверного состояния для установки cookie или генерации JWT.
