# ADR-003: Защита от IDOR при просмотре заказов

## Статус

Принято

## Контекст

При получении заказа по ID (GET /api/v1/orders/{id}) нужно убедиться, что заказ принадлежит текущему пользователю. Если обращение к чужому заказу возвращает 403 — злоумышленник знает, что такой заказ существует, и может перебирать UUID. Правило: всегда 404, никогда 403.

## Рассмотренные варианты

### 1. filter(user=request.user).get(id=...)

Запрос к БД с фильтрацией по user_id: `SELECT * FROM orders WHERE id = ? AND user_id = ?`. Если не найдено — 404. Один запрос, одно место проверки.

### 2. get(id=...) + проверка владельца отдельно

Сначала `SELECT * FROM orders WHERE id = ?`, потом проверка `if order.user_id != user_id`. Два условия в разных местах кода. Если забыть проверить — утечка IDOR.

### 3. Scope через permission class / decorator

Декоратор или Depends, который автоматически фильтрует по владельца. Масштабируемо, но избыточно для учебного проекта.

## Решение

**Вариант 1 — фильтрация в одном условии.**

## Обоснование

- **Читаемость кода**: Одно условие `order["id"] == order_id and order.get("user_id") == user_id` — сразу видно, что проверяется владение. Нет разброса логики по двум местам.
- **Поведение при неожиданном отсутствии**: Если заказ не найден ИЛИ он чужой — результат одинаковый: 404 ORDER_NOT_FOUND. Злоумышленник не может отличить «заказа нет» от «заказ чужой». Даже если забыть проверку — заказ просто не вернётся (нет в filtered set).
